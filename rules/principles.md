# 行動原則

実装・レビュー・タスク対応において常に適用する行動原則。悪例/良例のセットで意図を具体化する。

---

## 1. 確認してから進む（Think Before Coding）

### 悪い例 — 曖昧な要件のまま実装する

```
ユーザー: 検索機能を追加して
Claude:  [いきなり実装開始]
         SearchBar コンポーネントを作成しました。
         全フィールドに対してあいまい検索するロジックを追加しています...
```

### 良い例 — 前提を確認してから進む

```
ユーザー: 検索機能を追加して
Claude:  確認させてください:
         - 検索対象: タイトルのみ or 全フィールド？
         - マッチ方式: 前方一致 / 部分一致 / 全文検索？
         - リアルタイム検索 or 送信ボタン契機？
```

---

## 2. シンプルに保つ（Simplicity First）

### 悪い例 — 要求以上の抽象化・機能追加

```
ユーザー: ユーザー一覧ページに名前でのソートを追加して
Claude:  汎用ソートユーティリティを実装しました。
         - SortableColumn コンポーネント（再利用可能）
         - useSortState カスタムフック
         - ソートキー・方向・優先度の複合ソート対応
         - ローカルストレージへのソート設定の永続化
```

### 良い例 — 要求されたことだけを実装する

```
ユーザー: ユーザー一覧ページに名前でのソートを追加して
Claude:  users 配列を name で昇順ソートする処理を
         UserList コンポーネントに追加します。
         複合ソートや永続化は今回のスコープ外として省きます。
```

---

## 3. 必要な箇所だけ触る（Surgical Changes）

### 悪い例 — 関係ないコードまで変更する

```
ユーザー: getUserById 関数のバグを修正して
Claude:  バグを修正しました。
         あわせて以下も改善しました:
         - getUsers 関数のエラーハンドリングを統一
         - UserRepository クラスに型注釈を追加
         - 未使用の import を5ファイルで削除
         - コメントを日本語から英語に統一
```

### 良い例 — 指示されたバグだけ修正する

```
ユーザー: getUserById 関数のバグを修正して
Claude:  getUserById の id 比較で === を使っていなかった箇所を修正します。
         他のファイルにも気になる点がありましたが、
         今回のスコープ外のため別途提案できます。
```

### 悪い例 — 自分の変更で不要になったコードを残す

```typescript
// NG: fetchUserLegacy を新しい fetchUser に置き換えたのに定義を残したまま
async function fetchUserLegacy(id: string) { ... } // 自分が不要にしたのに残っている
async function fetchUser(id: string) { ... }
```

### 良い例 — 自分が作った不要なコードは削除する

```typescript
// OK: 置き換え元は自分が不要にしたので削除する
async function fetchUser(id: string) { ... }
```

## 4. ゴール基準で渡す（Goal-Driven Execution）

### 悪い例 — タスク指示（何をするか）で渡す

```
ユーザー: ログイン周りのバリデーションを追加して
```
→ 「何を追加するか」は伝わるが、何をもって完了とするかが不明。
  過不足のある実装をしても検証できない。

### 良い例 — 成功条件（どうなればOKか）で渡す

```
ユーザー: 以下のテストが pass するようにバリデーションを実装して:
         - メールアドレスが空のとき "メールアドレスを入力してください" を表示
         - パスワードが8文字未満のとき "8文字以上で入力してください" を表示
         - 正常な入力でフォームが送信される
```

### 変換例

| タスク指示（曖昧） | ゴール指示（検証可能） |
|---|---|
| エラーハンドリングを強化して | 以下のエラーケースで適切なメッセージが表示されるテストを書いて pass させて |
| パフォーマンスを改善して | Lighthouse スコアを 60 → 90 以上にして |
| コードを整理して | 循環参照の警告がゼロになるようにして |
| APIを安全にして | OWASP Top 10 のチェックリストに全項目 pass させて |
