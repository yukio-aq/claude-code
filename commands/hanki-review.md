# /hanki-review

`Daily/{案件名}/` 配下の日報を指定期間で集計し、自己評価レビュー（6項目）のドラフトを作成する。

## 引数

```
/hanki-review              # 直近6ヶ月を自動集計、全案件が対象
/hanki-review 2026-上期     # 期間ラベルを指定（ファイル名・出力に使う）
/hanki-review 2026-01-01..2026-06-30  # 期間を明示指定
```

## 実行手順

**Step 1**: 対象期間と対象ファイルを Bash で確定する。

```bash
VAULT="$HOME/Documents/Obsidian Vault"
DAILY_DIR="$VAULT/Daily"
REVIEW_DIR="$VAULT/Review"
mkdir -p "$REVIEW_DIR"

# $ARGUMENTS が "YYYY-MM-DD..YYYY-MM-DD" 形式ならそれを使う。
# それ以外（空 or ラベル文字列）なら直近6ヶ月を使う。
START=$(date -v-6m +%Y-%m-%d)
END=$(date +%Y-%m-%d)
echo "START=$START"
echo "END=$END"

# Daily/{案件名}/{YYYY-MM-DD}.md を案件ごとに列挙する
find "$DAILY_DIR" -mindepth 2 -maxdepth 2 -name '*.md' | sort
```

`$ARGUMENTS` が `YYYY-MM-DD..YYYY-MM-DD` 形式の場合は START/END をその値で上書きする。ラベルのみ（例: `2026-上期`）の場合は START/END は自動算出のまま、出力ファイル名にそのラベルを使う。

各ファイルの**親ディレクトリ名がそのまま案件名**になる。ファイル名（`YYYY-MM-DD.md`）を文字列比較して START〜END の範囲内のものだけを対象にする。対象が0件なら「集計対象の日報がありません（{DAILY_DIR}）」と伝えて終了する。

**Step 2**: 対象ファイルをすべて Read で読み込み、案件名（親ディレクトリ名）ごとにグルーピングする。`internal` は案件成果ではなく「社内活動・その他」として別枠で扱う。

**Step 3**: 案件ごとに以下4軸で事実を収集する。**日報に書かれていないことは書かない。** 推測や誇張はしない。

- **主な成果・アウトプット**: 完了したタスク・機能・修正（日報の「やったこと」から）
- **技術的成長・新スキル**: 新しく身につけた技術・挑戦した領域（日報の「学び・気づき」から）
- **課題・改善点**: つまずいた点・改善が必要だった点（日報の「学び・気づき」「次回やること」から）
- **定量実績**: 日報内に明記された件数・数値のみ拾う（PR数・修正件数など）。日報に数値が書かれていなければ「日報内に定量データの記載なし」と正直に書く。

**Step 4**: 収集した事実を、以下の自己評価レビュー6項目のドラフトに変換する。

```markdown
---
period: {期間ラベル or START〜END}
generated_from: {対象日報のファイル数}件の日報（{案件数}案件、{START} 〜 {END}）
status: draft — 提出前に必ず本人が内容・数値・等級要件照合を確認すること
---

# 自己評価レビュー ドラフト（{期間}）

## 1. プロジェクトや会社に貢献できた行動・成果（事実ベース）

> 等級要件との照合が必要な項目です。等級要件が手元にある場合はここに貼り付けて照合してください。
> （等級要件: 未貼付 — プレースホルダー）

{`internal` 以外の案件ごとに段落を分けて記述。各段落に以下を含める}

### {案件名}
- **役割**: {日報から判別できれば記載、不明なら「（日報からは不明。ご自身で補記してください）」}
- **成果・影響**: {日報に書かれた成果。単価・工数等の数値は日報記載があるものだけ}
- **具体的内容**: {やったことの要約}

{案件が複数あれば見出しを繰り返す}

### 社内活動・その他（internal）
{internal フォルダの日報があれば要約。なければこの見出し自体を省略}

## 2. 今半期の組織貢献度

**提案（要本人確認）**: {期待を大きく上回る / 期待をやや上回る / 期待通り / やや期待を下回る / 改善が必要 のいずれかを、集計した事実の量・インパクトから一次提案する}

> この提案は日報の記載量・内容から機械的に導いたものです。実際の評価は本人の判断で確定してください。

## 3. 2の理由

{業績貢献（成果・稼働実績）とチーム貢献・他者貢献（他メンバーへの寄与、組織課題解決）の観点で、日報の事実から理由を具体的に記述}

## 4. 今半期の成長度

**提案（要本人確認）**: {項目2と同じ5段階から一次提案}

## 5. 4の理由

{目標達成度、新しい知識・スキル獲得、チャレンジした内容を日報の「学び・気づき」から具体的に記述}

## 6. 組織貢献・自己成長のためにもっとやるべきだったこと / 今後やるべきこと

{日報の「課題・改善点」「次回やること」から抽出。今期分だけで判断材料が薄い場合はその旨明記}
```

**Step 5**: Write ツールで `{REVIEW_DIR}/{期間ラベル}.md` に保存する（期間ラベル未指定時は `{START}_{END}.md`）。

**Step 6**: 完了メッセージを出力する。

```
✅ 半期レビュードラフトを保存しました → {ファイルパス}
集計対象: {件数}件の日報（{案件数}案件、{START} 〜 {END}）
⚠️ 等級要件の照合・数値の最終確認・選択式項目の最終判断は必ずご自身で行ってください。
```
