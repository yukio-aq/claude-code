# /test

テスト戦略の設計・テストコードの実装・カバレッジ補完を行う。

## 使い方
/test                    # カバレッジを計測して不足を補完
/test <機能名>           # テスト戦略から設計（実装前に使う）
/test <ファイルパス>     # 特定ファイルのテストを作成・補完

## 例
/test
/test ユーザー認証
/test src/lib/date-utils.ts

## 実行内容

### 機能名を渡した場合（実装前・戦略設計）
1. `qa-engineer` でテストケース一覧・カバレッジ基準・境界値を設計する
2. テストケースをコメントとして先にファイルに書き出す（実装の地図）
3. `docs/test-strategies/<feature>.md` に保存する

### ファイルパスを渡した場合（実装中・並走）
1. 対象ファイルを読み込んでテスト対象を洗い出す
2. `test-implementer` で実装と並走しながらテストを作成する
3. 🔴 Red → 🟢 Green のサイクルを記録しながら進める

### 引数なしの場合（実装後・補完）
1. テストを実行してカバレッジを計測する
2. rules/testing.md の基準値を下回る箇所を特定する
3. `test-implementer` で不足テストを補完する
4. 再計測して基準値クリアを確認する

## テスト命名規則
```
should <動作> when <条件>
renders <状態> while <操作>
```
