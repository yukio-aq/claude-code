# 技術選定チェックリスト

## 必須確認項目

### メンテナンス状況

- [ ] 直近6ヶ月以内にコミットがあるか
- [ ] GitHubのIssueが放置されていないか
- [ ] 主要メンテナーが1人だけでないか（バスファクターのリスク）

### ライセンス

- [ ] 商用利用が可能か
- [ ] MIT または Apache 2.0（または同等）か
- [ ] コピーレフト（GPL等）でないか

### セキュリティ

- [ ] 既知の脆弱性がないか（npm audit / pip-audit）
- [ ] 過去のセキュリティ対応が迅速か

### 実績・コミュニティ

- [ ] 本番環境での利用実績があるか
- [ ] ドキュメントが充実しているか
- [ ] Stack Overflow / GitHub Discussionsに回答があるか

### 技術的適合性

- [ ] 既存スタックと相性が良いか
- [ ] TypeScript型定義が提供されているか（TSプロジェクト）
- [ ] バンドルサイズが許容範囲か（bundlephobia.com で確認）
- [ ] テストが書きやすいか（モック・DIが可能か）

### 将来性

- [ ] メジャーバージョンの破壊的変更の頻度が許容範囲か
- [ ] 将来的に自前実装に置き換えられるか（ロックイン度）
- [ ] 移行コストを払ってでも採用する価値があるか

## 判定基準

| 確認項目の通過数 | 判定                        |
| ---------------- | --------------------------- |
| 全項目通過       | ✅ 採用推奨                 |
| 1〜2項目未達     | ⚠️ リスクを認識した上で採用 |
| 3項目以上未達    | ❌ 採用見送り・代替を検討   |
